# Link Tagging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add per-user link tagging with a normalized `tags` / `link_tags` schema, nested JSON API responses, chip-based tag entry in the edit form, and multi-select OR tag filtering on the main page.

**Architecture:** Extend SQLite and PostgreSQL schemas via a synchronized `v0000003` migration adding `tags` and `link_tags` tables with `ON DELETE CASCADE` and transactional orphan-tag pruning. Return `{ links: { [keyword]: { target, tags } }, tags: [...] }` from `getLinks`, `saveLink`, and `deleteLink` without altering redirect lookups (`GET /<keyword>`). Update the single-file React UI to render clickable OR filter pills and row badges on the main page and a whitespace-delimited tag chip input on the create/edit page.

**Tech Stack:** Rust (Axum, Tokio, SQLx for SQLite & PostgreSQL, Serde), React 18, React Router (`HashRouter`), Vite + `vite-plugin-singlefile`.

**Spec:** [docs/superpowers/specs/2026-11-27-link-tags-design.md](../specs/2026-11-27-link-tags-design.md)

## Global Constraints

- All API endpoints remain on `/` via `?action=...` (`getLinks`, `saveLink`, `deleteLink`); no new top-level HTTP paths.
- All database queries and mutations are scoped by `user_id` for multi-user isolation.
- `db/sqlite/` and `db/postgres/` must have matching migration versions (`v0000003`); PostgreSQL objects live in the `golinks` schema.
- Go-link redirect lookup (`Database::get_link_target` / `handle_redirect`) must remain completely unaffected.
- Zero compiler warnings in both `cargo build` and `cargo test`; frontend builds cleanly to a single `frontend/dist/index.html`.
- Public repo privacy: use only generic placeholders (`example.com`, `docs`, `notes`, `gh`, `alice`, `bob`, `work`, `tools`) in code, tests, and docs.

## Review Focus

1. **Renaming a link onto an existing link with different tags:** Overwriting `docs` by renaming `gh` replaces `docs`'s tags with the submitted tags and auto-deletes any tags exclusively on either previous row. (Pinned in Task 2)
2. **Multi-user shared tag name cleanup:** When Alice and Bob both use tag `"work"` and Alice removes/deletes her last `"work"` link, Alice's `"work"` tag is deleted while Bob's `"work"` tag and link stay untouched. (Pinned in Task 2)
3. **Mixed-case, duplicate, padded, empty, and invalid tags in `saveLink`:** `[" Work ", "work", "", "  ", "DOCS"]` normalizes to `["docs", "work"]`; tags with internal whitespace (`"my tag"`) or >32 chars return `400 Bad Request`. (Pinned in Task 3)
4. **Incremental upgrade from `v0000002` to `v0000003`:** Existing users and links survive migration and accept tags immediately. (Pinned in Task 1)
5. **Uncommitted tag text on form submit:** Clicking Save while a word is still in the tag input box (without pressing Space/Tab/Add) commits that word before calling `saveLink`. (Pinned in Task 5)

- [ ] **Step 3: Implement `LinkEntry`, `LinksPayload`, and tag-aware `list_links`, `save_link`, `delete_link` in `src/db/mod.rs`**

- `list_links`: Query `links` (`link_id, link_keyword, link_target`) ordered by `link_keyword ASC`, query `link_tags JOIN tags` for `user_id` ordered by `tag_name ASC` to attach sorted tag names to each `LinkEntry`, and query `SELECT tag_name FROM tags WHERE user_id = ? ORDER BY tag_name ASC` for `LinksPayload.tags`.
- `save_link`: Inside a transaction (both SQLite and PostgreSQL branches):
  1. If `rename_from` is `Some(orig)`, delete the old link row (`ON DELETE CASCADE` removes its `link_tags`).
  2. Upsert into `links (...) ON CONFLICT (user_id, link_keyword) DO UPDATE SET link_target = EXCLUDED.link_target, updated_on = CURRENT_TIMESTAMP RETURNING link_id`.
  3. Delete existing `link_tags` for that `link_id`.
  4. For each tag in `tags`: `INSERT INTO tags (user_id, tag_name) VALUES (?, ?) ON CONFLICT (user_id, tag_name) DO NOTHING`, fetch `tag_id`, and `INSERT INTO link_tags (link_id, tag_id) VALUES (?, ?) ON CONFLICT (link_id, tag_id) DO NOTHING`.
  5. Prune unused tags for `user_id`: `DELETE FROM tags WHERE user_id = ? AND NOT EXISTS (SELECT 1 FROM link_tags WHERE link_tags.tag_id = tags.tag_id)`.
  6. Commit and return `self.list_links(user_id).await`.
- `delete_link`: Inside a transaction, delete the link for `(user_id, keyword)`; if `rows_affected == 0` return `Ok(None)`; otherwise prune unused tags for `user_id`, commit, and return `Ok(Some(self.list_links(user_id).await?))`.

### Task 5: Frontend Tag Chip Input on Create/Edit Page

**Files:**
- Modify: `frontend/src/components/EditLink.jsx`
- Modify: `frontend/src/styles.css`

**Interfaces:**
- Consumes: `links` (`{ [key]: { target, tags } }`), `onDataUpdated`, `onUnauthorized`, and `saveLink({ originalKey, key, target, tags })` from Task 4.
- Produces: Tag chip input field in `EditLink.jsx` where whitespace, `Tab` (when input has text), blur, clicking **Add**, or submitting **Save** converts typed words into boxed tag chips (`[tag ×]`), and `×` or `Backspace` on empty input removes chips.

- [ ] **Step 1: Implement tag chip input in `frontend/src/components/EditLink.jsx`**

- Initialize `targetInput` from `isExisting ? links[routeKeyword].target : ''` and `tags` state from `isExisting ? links[routeKeyword].tags : []`, plus `tagInput` state (`''`).
- Implement helper `commitTagText(rawText, currentTags)` that splits on `/\s+/`, trims, lowercases, ignores empty strings, deduplicates against `currentTags`, and returns the merged tag array.
- Wire tag input events:
  - `onChange`: if the new value contains whitespace (`/\s/.test(val)`), split off all whitespace-delimited words before the trailing segment into chips and keep the trailing non-whitespace segment (or `''` if ending in whitespace) in `tagInput`.
  - `onKeyDown`:
    - `Tab` when `tagInput.trim()` is non-empty: `e.preventDefault()`, commit `tagInput` into `tags`, clear `tagInput`.
    - `Backspace` when `tagInput === ''` and `tags.length > 0`: remove the last tag chip.
  - `onBlur`: if `tagInput.trim()` is non-empty, commit `tagInput` into `tags` and clear `tagInput`.
  - **Add** button (`type="button"`): commits `tagInput` into `tags`, clears `tagInput`, and refocuses the tag input.
- Render boxed chips (`.tag-chip`) inside a `.tag-input-box` container with a remove button (`×`, `aria-label="Remove tag <tag>"`), paired with the text `<input>` and an **Add** button.
- In `handleSave`: compute `const finalTags = commitTagText(tagInput, tags);` (so uncommitted text is never lost on Save), update state, and call `saveLink({ originalKey, key, target, tags: finalTags })`, then `onDataUpdated(updated)`.
- In `handleDelete`: pass `updated` to `onDataUpdated(updated)`.
